## 一、架构变更总览

```
迁移前                              迁移后

知识库向量    ES  ────────────────→  Milvus（可切换 ES/Milvus/Memory）
```

## 二、核心模式：数据源切换层

### 2.1 问题

多个存储后端（ES、Milvus、Memory），每个 API 不同，上层代码直接依赖具体实现会导致切换成本极高。

### 2.2 方案：抽象基类 + 工厂函数

```python
# vector_backend.py

class VectorBackend(ABC):
    @abstractmethod
    def add_documents(self, docs, embeddings) -> list[str]: ...
    @abstractmethod
    def search(self, query, query_vector, top_k) -> list[dict]: ...
    @abstractmethod
    def search_with_options(self, ...) -> list[dict]: ...
    @abstractmethod
    def list_documents(self) -> list[dict]: ...
    @abstractmethod
    def list_chunks(self, doc_id) -> list[dict]: ...
    @abstractmethod
    def delete_documents(self, doc_id): ...


def get_vector_backend() -> VectorBackend:
    if VECTOR_BACKEND == "milvus":
        return MilvusVectorBackend(...)
    if VECTOR_BACKEND == "elasticsearch":
        return ElasticsearchVectorBackend(...)
    if VECTOR_BACKEND == "memory":
        return MemoryVectorBackend()
```

### 2.3 关键点

- **上层代码只依赖 `backend` 实例**，不 import 具体类
- **切换只需改环境变量** `VECTOR_BACKEND`
- **惰性连接**：`MilvusVectorBackend` 构造时不连接，首次调用 `_mc` 属性时才 `MilvusClient(...)`，避免 import 时就因为网络不通而崩溃
- **ES 实现完整保留**，`get_vector_backend()` 改一行即可回退

### 3.1 Milvus 连接方式


**注意**：pymilvus 3.x 的 `MilvusClient` 不需要手动 `load_collection()` / `release_collection()`，内部自动处理。

### 3.2 核心踩坑：Schema 不匹配

**现象**：导入成功后 `list_documents()` 报错 `field metadata not exist: invalid parameter`

**原因**：代码假设 collection 有 `metadata`（JSON 类型）字段，但实际迁移后的 collection 用的是 `metadata_json`（VARCHAR 65535）+ 独立标量字段（`chunk_id`、`doc_id`、`filename` 等）。

**教训**：**先跑 `client.describe_collection()` 看实际 schema，再写代码**。

```python
# 查看实际 schema
schema = client.describe_collection("questrag_chunks")
for f in schema["fields"]:
    print(f"{f['name']}: type={f['type']} params={f.get('params', {})}")
```

**修复**：增加 `_parse_metadata()` 方法从 `metadata_json` 还原元数据：

```python
@staticmethod
def _parse_metadata(row: dict) -> dict:
    val = row.get("metadata_json", "{}")
    if isinstance(val, dict):
        return val
    if isinstance(val, str):
        try:
            return json.loads(val)
        except (json.JSONDecodeError, TypeError):
            return {}
    return {}
```

### 3.3 写入时映射所有字段

```python
def _doc_to_milvus_row(chunk_id, text, embedding, metadata):
    return {
        "id": chunk_id,
        "text": text,
        "embedding": embedding,
        # 独立标量字段（方便直接做标量过滤）
        "chunk_id": chunk_id,
        "doc_id": metadata.get("doc_id", ""),
        "chunk_index": metadata.get("chunk_index", 0),
        "filename": metadata.get("filename", ""),
        # ...
        # 完整元数据序列化到 metadata_json
        "metadata_json": json.dumps(metadata, ensure_ascii=False),
    }
```

### 3.4 评测临时集合

评测每次运行创建一个独立集合，结束后删除：

```python
def create_eval_collection(self, name: str, dims: int):
    from pymilvus import DataType, FieldSchema

    if self._mc.has_collection(name):
        self._mc.drop_collection(name)

    schema = self._mc.create_schema(auto_id=False, enable_dynamic_field=False)
    schema.add_field(FieldSchema(name="id", dtype=DataType.VARCHAR, is_primary=True, max_length=128))
    schema.add_field(FieldSchema(name="text", dtype=DataType.VARCHAR, max_length=65535))
    schema.add_field(FieldSchema(name="embedding", dtype=DataType.FLOAT_VECTOR, dim=dims))
    # ...

    index_params = self._mc.prepare_index_params()
    index_params.add_index(field_name="embedding", index_type="IVF_FLAT", metric_type="COSINE", ...)
    self._mc.create_collection(collection_name=name, schema=schema, index_params=index_params)

def drop_collection(self, name: str):
    self._mc.drop_collection(name)
```

**与 ES 对比**：

| 维度 | ES 临时索引 | Milvus 临时集合 |
|------|------------|----------------|
| 创建复杂度 | 无需预定义 mapping | 需预设 schema |
| 创建速度 | 毫秒级 | 秒级 |
| 删除 | `delete_index()` | `drop_collection()` |
| 搜索前置 | 无 | 自动 load（MilvusClient 内部处理） |

## 四、ES → PostgreSQL 岗位数据迁移

### 4.1 为什么不直接用 pgvector

PG 服务器未安装 `pgvector` 扩展（`CREATE EXTENSION vector` 失败于 `vector.control not found`），且不方便操作服务器安装。

### 4.2 替代方案：double precision[]

```sql
CREATE TABLE IF NOT EXISTS jobs (
    id TEXT PRIMARY KEY,
    title TEXT,
    company TEXT,
    -- ...
    embedding double precision[],
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);
```

优点：
- 不依赖任何 PG 扩展
- 1000 条数据量下，Python 侧算余弦相似度完全够用

### 4.3 向量搜索：Python 侧计算

```python
def vector_search_jobs(query_vector: list[float], top_k: int) -> list[dict]:
    # 查出所有带 embedding 的行
    rows = conn.execute("SELECT * FROM jobs WHERE embedding IS NOT NULL").fetchall()
    # Python 侧计算余弦相似度
    for r in rows:
        r["similarity"] = _cosine_similarity(query_vector, r["embedding"])
    rows.sort(key=lambda r: r["similarity"], reverse=True)
    return rows[:top_k]
```

**适用条件**：数据量 < 1万条。超过则需要 pgvector 的 HNSW 索引加速。

### 4.4 ES scroll 批量导出

```python
resp = es.search(index=index_name, query={"match_all": {}}, size=500, scroll="2m")
scroll_id = resp["_scroll_id"]
```

### 4.5 关键词搜索：ILIKE + ts_rank

```sql
SELECT *, ts_rank(
    to_tsvector('simple', coalesce(content,'') || ' ' || coalesce(title,'') || ...),
    plainto_tsquery('simple', $1)
) AS rank
FROM jobs
WHERE title ILIKE $2 OR company ILIKE $2 OR ...
ORDER BY rank DESC
LIMIT $3
```

**注意**：`'simple'` 配置对中文分词效果有限，但结合 ILIKE 作为 fallback，实际够用。

## 五、数据库切换

### 5.1 连接串管理

**原则**：密码只放 `.env`，`config.py` 默认值不包含任何凭证。

```python
# config.py —— 默认值安全
DATABASE_URL = os.environ.get("DATABASE_URL", "")

# .env —— 真实凭证（已在 .gitignore）
DATABASE_URL="postgresql://vector_user:vector_pass@192.168.1.43:5433/vector_db"
```

### 5.2 迁移评测数据

旧库 `quest_rag`（`postgres:difyai123456@192.168.1.43:5432`）中的评测表直接 SELECT/INSERT 到新库。

**JSONB 列的坑**：psycopg 不能自动适配 Python `dict` 到 JSONB，需要手动 `json.dumps()`：

```python
JSONB_COLS = {
    "evaluation_runs": ["document_scope", "clean_options", "split_options", ...],
    "evaluation_items": ["expected_source_ids", "retrieval_queries", "retrieved", "metrics"],
    ...
}

for col in columns:
    val = row[col]
    if col in jsonb_set:
        values[col] = json.dumps(val, ensure_ascii=False, default=str)
    else:
        values[col] = val
```
