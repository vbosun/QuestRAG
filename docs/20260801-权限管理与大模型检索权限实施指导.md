# QuestRAG 权限管理与大模型检索权限实施指导

> 目标：在已有登录认证基础上，实现角色-权限访问控制、权限管理菜单、用户/角色管理、后端 API 权限、大模型工具权限，以及用户访问大模型时的 RAG 检索范围权限。本文面向执行 Agent，要求按模块清晰落地，避免只做前端隐藏或 prompt 约束。

## 1. 核心结论

QuestRAG 的权限体系分三类：

```text
系统功能权限
  控制菜单、路由、按钮、后端 API。
  示例：knowledge.document.upload、system.config.update。

大模型工具权限
  控制 Agent 可以注册和调用哪些工具。
  示例：llm.tool.knowledge_search、llm.tool.job_search。

RAG 检索范围权限
  控制用户问大模型时，检索器可以在哪些知识范围内召回。
  示例：rag.scope.public_policy、rag.scope.jobs、rag.scope.evaluation_docs。
```

前端权限只负责体验：

```text
菜单隐藏
路由拦截
按钮禁用
403 页面
```

真正安全边界必须在后端：

```text
API 执行前校验权限
Agent 工具注册前过滤
工具执行前二次校验
检索工具发起检索前构造权限过滤条件
向量库 / PgSQL / 关键词检索只检索允许范围
```

一句话原则：

```text
用户无权访问的知识，不能进入检索候选集，不能进入 LLM 上下文，不能出现在引用来源里。
```

## 2. 当前工程切入点

当前工程已经有登录认证的雏形：

```text
quest_rag/auth/
  schemas.py
  dependencies.py
  security.py
  service.py
  store.py
  redis_store.py

quest_rag/api/auth.py
```

当前 `CurrentUser` 仍是单角色模型：

```python
class CurrentUser(BaseModel):
    id: int
    sid: str
    role: str
    status: int
    full_name: str | None = None
    id_number_masked: str | None = None
    token_version: int
```

权限实施后要扩展为：

```python
class CurrentUser(BaseModel):
    id: int
    sid: str
    roles: list[str]
    permissions: list[str]
    rag_scopes: list[str]
    status: int
    full_name: str | None = None
    id_number_masked: str | None = None
    token_version: int
```

当前检索入口：

```text
quest_rag/rag/document_retriever.py
  search(query, top_k=None)
    -> get_embedding(query)
    -> backend.search_with_options(...)
```

权限实施后要演进为：

```python
search(
    query: str,
    top_k: int | None = None,
    current_user: CurrentUser | None = None,
    requested_scopes: list[str] | None = None,
    requested_doc_ids: list[str] | None = None,
)
```

并将权限过滤条件传入：

```python
backend.search_with_options(..., permission_filter=permission_filter)
```

## 3. 权限原则

必须遵守以下原则：

```text
1. 默认拒绝
   没有声明权限 -> 禁止
   没有匹配权限 -> 禁止
   工具没有 permission 元数据 -> 禁止注册

2. 后端强制
   前端隐藏菜单不是安全边界。
   所有敏感 API 必须 require_permission。

3. 工具双重控制
   Agent 构造工具列表前过滤一次。
   工具执行入口再校验一次。

4. 检索前过滤
   RAG 权限过滤要在检索工具内部、真正调用 retriever/backend 前完成。
   优先把过滤条件下推到 Elasticsearch/Milvus/PgSQL 查询。

5. 权限不固化在 JWT
   JWT 只保存 user_id、sid、token_version 等。
   roles、permissions、rag_scopes 由 Redis session 或后端实时加载。

6. 审计可追溯
   用户管理、角色管理、权限变更、工具调用、权限拒绝都要记录审计日志。
```

## 4. 数据库设计

第一阶段继续使用 `init_auth_db()` 建表。可以在 `quest_rag/auth/store.py` 中扩展，也可以新增 `quest_rag/auth/permission_store.py` 并在启动时调用 `init_permission_db()`。建议新增独立文件，避免 `store.py` 过大。

### 4.1 角色表

```sql
CREATE TABLE IF NOT EXISTS auth_role (
    id BIGSERIAL PRIMARY KEY,
    code VARCHAR(64) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    status SMALLINT NOT NULL DEFAULT 1,
    system_builtin BOOLEAN NOT NULL DEFAULT false,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_auth_role_status
ON auth_role(status);
```

字段说明：

```text
code            角色编码，例如 ADMIN、OPERATOR、USER
name            中文名称，例如 系统管理员、业务经办员
description     角色说明
status          1=启用，0=停用
system_builtin  是否内置角色；内置角色不允许删除
```

### 4.2 权限表

```sql
CREATE TABLE IF NOT EXISTS auth_permission (
    id BIGSERIAL PRIMARY KEY,
    code VARCHAR(128) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    type VARCHAR(32) NOT NULL,
    resource VARCHAR(128),
    action VARCHAR(64),
    risk_level VARCHAR(32),
    group_code VARCHAR(64),
    description TEXT NOT NULL DEFAULT '',
    system_builtin BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_auth_permission_type
ON auth_permission(type);

CREATE INDEX IF NOT EXISTS idx_auth_permission_group
ON auth_permission(group_code);
```

`type` 建议值：

```text
MENU       菜单权限
ROUTE      前端路由权限
API        后端接口权限
ACTION     页面按钮/操作权限
LLM_TOOL   大模型工具权限
```

`risk_level` 建议值：

```text
LOW       只读检索
MEDIUM    运行评测、生成草稿
HIGH      文档入库、删除、修改系统配置
CRITICAL  用户管理、权限管理
```

### 4.3 用户角色关系表

```sql
CREATE TABLE IF NOT EXISTS auth_account_role (
    account_id BIGINT NOT NULL REFERENCES auth_account(id) ON DELETE CASCADE,
    role_id BIGINT NOT NULL REFERENCES auth_role(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (account_id, role_id)
);

CREATE INDEX IF NOT EXISTS idx_auth_account_role_role
ON auth_account_role(role_id);
```

### 4.4 角色权限关系表

```sql
CREATE TABLE IF NOT EXISTS auth_role_permission (
    role_id BIGINT NOT NULL REFERENCES auth_role(id) ON DELETE CASCADE,
    permission_id BIGINT NOT NULL REFERENCES auth_permission(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (role_id, permission_id)
);

CREATE INDEX IF NOT EXISTS idx_auth_role_permission_permission
ON auth_role_permission(permission_id);
```

### 4.5 RAG 检索范围表

RAG scope 单独建表，不要混成普通 API 权限。原因是它控制的是大模型检索可见范围，不是页面或接口。

```sql
CREATE TABLE IF NOT EXISTS rag_scope (
    id BIGSERIAL PRIMARY KEY,
    code VARCHAR(64) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    description TEXT NOT NULL DEFAULT '',
    status SMALLINT NOT NULL DEFAULT 1,
    system_builtin BOOLEAN NOT NULL DEFAULT true,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE IF NOT EXISTS auth_role_rag_scope (
    role_id BIGINT NOT NULL REFERENCES auth_role(id) ON DELETE CASCADE,
    scope_id BIGINT NOT NULL REFERENCES rag_scope(id) ON DELETE CASCADE,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    PRIMARY KEY (role_id, scope_id)
);
```

### 4.6 LLM 工具调用日志

```sql
CREATE TABLE IF NOT EXISTS llm_tool_call_log (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT REFERENCES auth_account(id) ON DELETE SET NULL,
    session_id TEXT,
    conversation_id TEXT,
    tool_name VARCHAR(128) NOT NULL,
    permission_code VARCHAR(128),
    allowed BOOLEAN NOT NULL DEFAULT false,
    deny_reason TEXT,
    requested_scopes JSONB NOT NULL DEFAULT '[]'::jsonb,
    effective_scopes JSONB NOT NULL DEFAULT '[]'::jsonb,
    requested_doc_ids JSONB NOT NULL DEFAULT '[]'::jsonb,
    effective_doc_ids JSONB NOT NULL DEFAULT '[]'::jsonb,
    input_summary TEXT,
    output_summary TEXT,
    latency_ms INTEGER,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_llm_tool_call_log_user_time
ON llm_tool_call_log(user_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_llm_tool_call_log_tool_time
ON llm_tool_call_log(tool_name, created_at DESC);
```

注意：

```text
input_summary / output_summary 必须脱敏。
不要记录完整身份证号、完整 token、完整密码、完整内部文档内容。
```

## 5. 文档与 Chunk 权限元数据

用户访问大模型时的检索权限，需要落在文档和 chunk metadata 上。文档入库时必须写入这些字段。

建议文档级字段：

```text
scope_code
visibility
department_id
owner_user_id
security_level
```

建议值：

```text
scope_code:
  public_policy
  jobs
  evaluation_docs
  internal_policy
  department_docs
  private_docs

visibility:
  PUBLIC
  INTERNAL
  PRIVATE

security_level:
  PUBLIC
  INTERNAL
  SENSITIVE
  SECRET
```

第一阶段可以先只实现：

```text
public_policy
jobs
evaluation_docs
```

文档上传/确认入库时，在 `metadata` 中写入：

```python
metadata={
    ...
    "scope_code": req.metadata.scope_code or "public_policy",
    "visibility": req.metadata.visibility or "PUBLIC",
    "security_level": req.metadata.security_level or "PUBLIC",
    "owner_user_id": current_user.id,
}
```

如果前端暂时没有选择项：

```text
普通知识库文档 -> public_policy
岗位库 -> jobs
评测文档 -> evaluation_docs
```

## 10. CurrentUser 与 /auth/me

### 10.1 CurrentUser 聚合

登录成功或解析 token 后，需要聚合：

```text
roles
permissions
rag_scopes
```

聚合 SQL 逻辑：

```text
auth_account -> auth_account_role -> auth_role
auth_role -> auth_role_permission -> auth_permission
auth_role -> auth_role_rag_scope -> rag_scope
```

停用角色不生效：

```sql
WHERE auth_role.status = 1
```

停用 scope 不生效：

```sql
WHERE rag_scope.status = 1
```

### 10.2 /auth/me 响应

`/auth/me` 建议返回：

```json
{
  "id": 1,
  "full_name": "管理员",
  "id_number_masked": "1101************01",
  "status": 1,
  "roles": ["ADMIN"],
  "permissions": [
    "chat.view",
    "permission.manage",
    "permission.user.view"
  ],
  "rag_scopes": [
    "public_policy",
    "jobs",
    "evaluation_docs"
  ]
}
```

前端用这些字段过滤菜单和路由。

### 10.3 Redis session

Redis session 建议保存权限快照：

```json
{
  "user_id": 1,
  "roles": ["ADMIN"],
  "permissions": ["chat.view", "permission.manage"],
  "rag_scopes": ["public_policy", "jobs"],
  "token_version": 1
}
```

权限变更后第一阶段采用简单可靠策略：

```text
用户角色变更 -> 删除该用户所有 Redis session -> 要求重新登录
角色权限变更 -> 删除拥有该角色的用户 session -> 要求重新登录
```

后续可优化为刷新 Redis 权限快照。

## 11. 后端权限依赖

保留 `require_role()`，但新增 `require_permission()`，业务代码优先使用 permission。

```python
def require_permission(permission_code: str):
    def dependency(current_user: CurrentUser = Depends(get_current_user)) -> CurrentUser:
        if permission_code not in current_user.permissions:
            raise HTTPException(
                status_code=403,
                detail={"code": "FORBIDDEN", "message": "权限不足"},
            )
        return current_user
    return dependency
```

也可增加：

```python
require_any_permission(["a", "b"])
require_all_permissions(["a", "b"])
```

高风险接口示例：

```python
@router.post("/documents/stage")
async def stage_document(
    file: UploadFile = File(...),
    current_user: CurrentUser = Depends(require_permission("knowledge.document.upload")),
):
    ...

@router.post("/documents/stage/commit")
def commit_stage(
    req: DocumentStageRequest,
    current_user: CurrentUser = Depends(require_permission("knowledge.document.commit")),
):
    ...

@router.put("/system/config")
def update_config(
    req: ConfigUpdateRequest,
    current_user: CurrentUser = Depends(require_permission("system.retrieval_config.update")),
):
    ...
```

### 16.2 Agent 工具构造

```python
def build_tools_for_user(current_user: CurrentUser):
    tools = []
    for tool_name, spec in TOOL_REGISTRY.items():
        permission = spec.get("permission")
        if not permission:
            continue
        if permission not in current_user.permissions:
            continue
        if spec.get("risk_level") in {"HIGH", "CRITICAL"}:
```

## 17. RAG 检索权限

这是本方案最关键部分。

用户问大模型时，检索工具必须在检索前过滤。

正确流程：

```text
用户提问
  -> get_current_user
  -> Agent 只拿到允许的工具
  -> knowledge_search 工具被调用
  -> 工具读取 current_user.rag_scopes
  -> 与模型请求的 scopes/doc_ids 取交集
  -> 构造 permission_filter
  -> 调用 document_retriever.search(..., permission_filter)
  -> backend 搜索时下推过滤条件
  -> LLM 只收到有权限 chunks
  -> citations 只返回有权限来源
```

错误流程：

```text
全库检索
  -> rerank / RRF / 日志 / artifact
  -> 最后给 LLM 前过滤
```

这个不符合安全要求。只能作为短期过渡，而且过滤前结果不能进入日志、artifact、LLM 上下文、前端响应。

### 17.1 权限过滤构造

新增：

```text
quest_rag/rag/retrieval_permissions.py
```

示例：

```python
class RetrievalPermissionFilter(BaseModel):
    scope_codes: list[str]
    doc_ids: list[str] | None = None
    visibility: list[str] | None = None
    security_levels: list[str] | None = None
```

构造逻辑：

```python
def build_retrieval_permission_filter(
    current_user: CurrentUser,
    requested_scopes: list[str] | None = None,
    requested_doc_ids: list[str] | None = None,
) -> RetrievalPermissionFilter:
    allowed_scopes = set(current_user.rag_scopes)
    requested = set(requested_scopes or allowed_scopes)
    effective_scopes = sorted(allowed_scopes & requested)

    if not effective_scopes:
        return RetrievalPermissionFilter(scope_codes=[])

    return RetrievalPermissionFilter(scope_codes=effective_scopes)
```

如果模型传入了 `requested_doc_ids`，必须取交集，不允许扩大：

```python
effective_doc_ids = requested_doc_ids & allowed_doc_ids
```

第一阶段如果不做文档 ACL，可以先只按 `scope_code` 控制。

### 17.2 document_retriever 接口

从：

```python
def search(query: str, top_k: int | None = None) -> list[Document]:
```

改为：

```python
def search(
    query: str,
    top_k: int | None = None,
    permission_filter: RetrievalPermissionFilter | None = None,
) -> list[Document]:
```

调用：

```python
return backend.search_with_options(
    query,
    query_vector,
    top_k,
    mode=cfg["mode"],
    recall_k=cfg["recall_k"],
    rrf_k=cfg["rrf_k"],
    permission_filter=permission_filter,
)
```

### 17.3 VectorBackend 接口

扩展抽象类：

```python
def search_with_options(
    self,

    query_vector: list[float],
```

### 17.4 Elasticsearch 过滤

Elasticsearch 当前 `_vector_search()` 使用 `script_score` + `match_all`，`_keyword_search()` 使用 `match`。需要把权限过滤加入 query。

构造 filter：

```python
def _build_es_filter(permission_filter):
    filters = []
    if permission_filter and permission_filter.scope_codes:
        filters.append({"terms": {"metadata.scope_code": permission_filter.scope_codes}})
    if permission_filter and permission_filter.doc_ids:
        filters.append({"terms": {"metadata.doc_id": permission_filter.doc_ids}})
    return filters
```

向量：

```python
query={
    "script_score": {
        "query": {
            "bool": {
                "filter": filters or [{"match_all": {}}]
            }
        },
        "script": {
            "source": "cosineSimilarity(params.query_vector, 'embedding') + 1.0",
            "params": {"query_vector": query_vector},
        },
    }
}
```

关键词：

```python
query={
    "bool": {
        "must": [{"match": {"text": query}}],
        "filter": filters,
    }
}
```

注意：Elasticsearch mapping 需要给 `metadata.scope_code` 增加 keyword 映射。新索引建立即可，旧索引需要重建或兼容缺省。

### 17.5 Milvus 过滤

当前 Milvus schema 有显式字段：

```text
doc_id
filename
source_type
document_category
metadata_json
```

`metadata_json` 是字符串，不适合高效过滤 `scope_code`。建议新增显式字段：

```text
scope_code VARCHAR
visibility VARCHAR
security_level VARCHAR
owner_user_id INT64 或 VARCHAR
department_id VARCHAR
```

`_doc_to_milvus_row()` 增加：

```python
"scope_code": str(metadata.get("scope_code", "public_policy")),
"visibility": str(metadata.get("visibility", "PUBLIC")),
"security_level": str(metadata.get("security_level", "PUBLIC")),
"owner_user_id": str(metadata.get("owner_user_id", "")),
"department_id": str(metadata.get("department_id", "")),
```

Milvus filter 示例：

```python
scope_filter = 'scope_code in ["public_policy", "jobs"]'
```

如果同时按文档：

```python
doc_filter = 'doc_id in ["kb::xxx", "kb::yyy"]'
```

组合：

```python
filter = f"({scope_filter}) and ({doc_filter})"
```

向量 search：

```python
self._mc.search(
    collection_name=self._collection_name,
    data=[query_vector],
    anns_field="embedding",
    search_params={"metric_type": "COSINE"},
    limit=top_k,
    filter=filter,
    output_fields=self._QUERY_CORE,
)
```

关键词 query：

```python
filter=f'({permission_expr}) and text_match(text, "{escaped}")'
```

如果旧 collection 无法新增字段，短期过渡：

```text
1. 新文档 metadata_json 写 scope_code
2. 检索 topK * 5
3. 后端过滤 metadata.scope_code
4. 不足继续扩大召回
5. 尽快重建 Milvus collection
```

过渡期禁止记录过滤前结果。

### 17.6 Memory backend 过滤

内存 backend 直接在搜索前过滤 `vector_store`：

```python
filtered_store = [
    chunk for chunk in vector_store
    if chunk["metadata"].get("scope_code") in permission_filter.scope_codes
]
```

然后再做 vector/keyword search。

## 25. 执行注意事项

1. 不要把权限 code 写散在前后端各处。先集中定义常量或 catalog seed。
2. 不要把完整 permissions 长期塞进 JWT。
3. 不要只隐藏前端菜单，后端必须校验。
4. 不要让模型通过 prompt 自觉遵守工具权限。
5. 不要全库检索后再把无权限内容给 LLM 前过滤。
6. 不要记录过滤前检索结果。
7. 不要让用户直接分配零散权限，第一阶段用用户分配角色。
8. 不要让当前管理员移除自己的最后管理能力。
9. 权限变更后优先强制重新登录，简单可靠。
10. 每次高风险管理操作都写审计日志。
