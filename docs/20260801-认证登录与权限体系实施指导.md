# QuestRAG 认证登录与权限体系实施指导

> 目标：为 QuestRAG 增加政务行业可落地的登录认证体系。第一阶段实现身份证号 + 密码登录、JWT access token + refresh token、Redis 会话白名单、退出登录、登录失效回登录页、个人管理和修改密码；同时为后续角色权限管理预留结构。

## 1. 设计结论

本次不要把认证逻辑混入 RAG、文档、评测模块，而是新增独立认证域。

推荐方案：

```text
FastAPI 后端
  - PgSQL：保存个人信息、账号凭证、登录日志、操作日志
  - Redis：保存在线 session、token 有效性、登录失败计数
  - JWT：作为请求携带的签名凭证

React 前端
  - React Router：登录页、工作台页、个人管理页
  - AuthProvider：保存登录状态和当前用户
  - ProtectedRoute：未登录或登录失效时跳转 /login
  - request 封装：自动携带 access_token，access 过期时 refresh 续期
```

第一阶段固定使用身份证号登录，暂不允许用户名登录。后续如需账号名、手机号、统一身份认证平台、政务 OAuth/SSO，可在认证域内扩展，不影响 RAG 业务模块。

## 2. 认证流程

### 2.1 首次打开系统

```text
用户访问前端
  -> 前端加载 AuthProvider
  -> 若无本地登录状态，跳转 /login
  -> 若有 access_token，调用 /auth/me 校验
  -> 校验成功进入 /app/chat
  -> 校验失败清空登录态并跳转 /login
```

### 2.2 登录流程

```text
用户输入身份证号 + 密码
  -> POST /auth/login
  -> 后端规范化身份证号
  -> 计算 id_number_digest
  -> PgSQL 查询 auth_account
  -> 校验账号状态
  -> 校验 Redis 登录失败锁定状态
  -> 校验密码哈希
  -> 生成 session_id
  -> 签发 access_token 和 refresh_token
  -> Redis 写入 auth:session:{session_id}
  -> Redis 写入 auth:user_sessions:{user_id}
  -> PgSQL 写 auth_login_log 成功日志
  -> 更新 auth_account.last_login_at / last_login_ip
  -> 前端保存 token 和 user_info
  -> 跳转 /app/chat
```

失败时：

```text
账号不存在 / 密码错误
  -> 返回统一错误：“身份证号或密码错误”
  -> 不向前端暴露账号是否存在
  -> Redis 累加失败次数
  -> PgSQL 写登录失败日志

账号禁用 / 锁定
  -> 返回 403
  -> 前端展示明确提示：“账号已禁用，请联系管理员”
```

### 2.3 普通业务请求

```text
前端请求 /chat/stream、/documents/*、/evaluations/*、/system/*
  -> request() 自动携带 Authorization: Bearer <access_token>
  -> 后端 Depends(get_current_user)
  -> 校验 JWT 签名、过期时间、type=access
  -> 读取 payload 中的 sub、sid、jti、role、token_version
  -> Redis 查询 auth:session:{sid}
  -> 比对 user_id、role、token_version
  -> PgSQL 可选检查账号 status
  -> 注入 current_user
  -> 执行业务接口
```

### 2.4 Access Token 过期续期

```text
业务接口返回 401，错误码 ACCESS_TOKEN_EXPIRED
  -> 前端调用 POST /auth/refresh
  -> 后端校验 refresh_token
  -> 校验 Redis session 是否存在
  -> 校验 token_version
  -> 签发新的 access_token
  -> 前端更新 access_token
  -> 重试原请求一次
```

refresh 失败时：

```text
refresh_token 过期 / session 不存在 / token_version 不匹配
  -> 返回 401
  -> 前端清空登录态
  -> 跳转 /login
```

### 2.5 退出登录

```text
用户点击退出登录
  -> POST /auth/logout
  -> 后端读取 current_user.sid
  -> 删除 Redis auth:session:{sid}
  -> 从 auth:user_sessions:{user_id} 移除 sid
  -> PgSQL 写 auth_operation_log
  -> 前端清空 token 和 user_info
  -> 跳转 /login
```

### 2.6 修改密码

```text
用户进入 /app/profile/password
  -> 输入旧密码、新密码、确认新密码
  -> POST /auth/change-password
  -> 后端校验当前用户
  -> 校验旧密码
  -> 校验新密码复杂度
  -> 更新 password_hash、password_changed_at、token_version
  -> 删除该用户所有 Redis session
  -> PgSQL 写 auth_operation_log
  -> 前端提示“密码已修改，请重新登录”
  -> 跳转 /login
```

修改密码后强制重新登录，避免旧 token 继续使用。

## 3. 后端模块结构

新增目录：

```text
quest_rag/auth/
  __init__.py
  dependencies.py
  redis_store.py
  schemas.py
  security.py
  service.py
  store.py

quest_rag/api/auth.py
```

职责说明：

| 文件 | 职责 |
|---|---|
| `quest_rag/api/auth.py` | FastAPI 路由层，只负责请求/响应和 HTTP 状态码 |
| `quest_rag/auth/schemas.py` | Pydantic 请求和响应模型 |
| `quest_rag/auth/service.py` | 登录、刷新、退出、修改密码等业务编排 |
| `quest_rag/auth/store.py` | PgSQL 访问，包含 `init_auth_db()` |
| `quest_rag/auth/redis_store.py` | Redis session、失败计数、用户 session 集合 |
| `quest_rag/auth/security.py` | JWT、密码哈希、身份证摘要、脱敏、密码策略 |
| `quest_rag/auth/dependencies.py` | `get_current_user`、`require_role`、`require_permission` |

`main.py` 需要做两件事：

```python
from quest_rag.api import auth
from quest_rag.auth.store import init_auth_db

app.include_router(auth.router)

@app.on_event("startup")
def startup():
    init_db()
    init_auth_db()
    load_system_config()
```

注意：实际修改时要保留现有 PostgreSQL 初始化异常处理策略，不要因为认证表初始化失败把错误吞得太干净。认证失败应视为系统不可用，而不是“工作台暂不可用”。

- 生产环境不要复用开发 Redis 密码。

## 5. 数据库表设计

第一阶段使用 `init_auth_db()` 建表，后续成熟后再迁移到 Alembic。

### 5.1 个人基本信息表

```sql
CREATE TABLE IF NOT EXISTS personal_info (
    id BIGSERIAL PRIMARY KEY,
    id_number_ciphertext TEXT,
    id_number_digest TEXT UNIQUE NOT NULL,
    full_name VARCHAR(50) NOT NULL,
    phone VARCHAR(20),
    gender VARCHAR(10),
    birth_date DATE,
    address TEXT,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_personal_info_id_number_digest
ON personal_info(id_number_digest);
```

说明：

- `id_number_digest` 用于查询和唯一约束。
- `id_number_ciphertext` 用于必要场景下回显或审计，第一阶段如果暂不做加密，可以先留空或先不返回明文。
- 不建议用身份证号明文建唯一索引。

### 5.2 登录账号表

```sql
CREATE TABLE IF NOT EXISTS auth_account (
    id BIGSERIAL PRIMARY KEY,
    personal_info_id BIGINT NOT NULL REFERENCES personal_info(id) ON DELETE CASCADE,
    id_number_digest TEXT UNIQUE NOT NULL,
    password_hash TEXT NOT NULL,
    role VARCHAR(32) NOT NULL DEFAULT 'USER',
    status SMALLINT NOT NULL DEFAULT 1,
    token_version INTEGER NOT NULL DEFAULT 1,
    failed_login_count INTEGER NOT NULL DEFAULT 0,
    locked_until TIMESTAMPTZ,
    password_changed_at TIMESTAMPTZ,
    last_login_at TIMESTAMPTZ,
    last_login_ip VARCHAR(45),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now(),
    updated_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_auth_account_id_number_digest
ON auth_account(id_number_digest);

CREATE INDEX IF NOT EXISTS idx_auth_account_personal_info_id
ON auth_account(personal_info_id);
```

`status` 建议定义：

| 值 | 含义 |
|---|---|
| `1` | 启用 |
| `0` | 禁用 |
| `-1` | 锁定 |

第一阶段角色先用字符串：

| 角色 | 含义 |
|---|---|
| `USER` | 普通用户 |
| `ADMIN` | 管理员 |
| `SYSTEM` | 系统账号，预留 |

后续做完整 RBAC 时再新增 `auth_role`、`auth_permission`、`auth_role_permission`。

### 5.3 登录日志表

```sql
CREATE TABLE IF NOT EXISTS auth_login_log (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT REFERENCES auth_account(id) ON DELETE SET NULL,
    id_number_digest TEXT,
    login_time TIMESTAMPTZ NOT NULL DEFAULT now(),
    login_ip VARCHAR(45),
    user_agent TEXT,
    status SMALLINT NOT NULL,
    fail_reason VARCHAR(100)
);

CREATE INDEX IF NOT EXISTS idx_auth_login_log_user_time
ON auth_login_log(user_id, login_time DESC);

CREATE INDEX IF NOT EXISTS idx_auth_login_log_digest_time
ON auth_login_log(id_number_digest, login_time DESC);
```

### 5.4 操作日志表

```sql
CREATE TABLE IF NOT EXISTS auth_operation_log (
    id BIGSERIAL PRIMARY KEY,
    user_id BIGINT REFERENCES auth_account(id) ON DELETE SET NULL,
    action VARCHAR(80) NOT NULL,
    target_type VARCHAR(80),
    target_id TEXT,
    request_ip VARCHAR(45),
    user_agent TEXT,
    detail JSONB NOT NULL DEFAULT '{}'::jsonb,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE INDEX IF NOT EXISTS idx_auth_operation_log_user_time
ON auth_operation_log(user_id, created_at DESC);

CREATE INDEX IF NOT EXISTS idx_auth_operation_log_action_time
ON auth_operation_log(action, created_at DESC);
```

第一阶段至少记录：

- `LOGIN`
- `LOGOUT`
- `CHANGE_PASSWORD`
- `REFRESH_TOKEN_FAILED`
- `KICK_USER`，预留
- `DISABLE_USER`，预留

## 6. Redis 设计

Redis 用来管理在线状态和短期安全状态。

### 6.1 Session Key

```text
auth:session:{sid}
```

值建议为 JSON：

```json
{
  "sid": "uuid",
  "user_id": 1,
  "role": "ADMIN",
  "status": 1,
  "token_version": 1,
  "login_ip": "127.0.0.1",
  "user_agent": "Mozilla/5.0",
  "created_at": "2026-08-01T10:00:00+08:00",
  "expires_at": "2026-08-01T18:00:00+08:00"
}
```

TTL：

```text
AUTH_REFRESH_TOKEN_HOURS * 3600
```

### 6.2 用户 Session 集合

```text
auth:user_sessions:{user_id}
```

类型：Redis Set。

用途：

- 用户修改密码后删除全部 session。
- 管理员强制下线时删除全部 session。
- 后续可展示“当前登录设备”。

### 6.3 登录失败计数

```text
auth:login_fail:{id_number_digest}:{ip}
```

策略：

```text
失败 1 次：INCR，设置 TTL 15 分钟
达到 5 次：返回锁定提示
登录成功：删除失败计数
```

也可以同时写 PgSQL 的 `failed_login_count` 和 `locked_until`，但第一阶段 Redis 锁定足够；PgSQL 留字段用于后续后台管理和审计。

## 7. JWT 设计

### 7.1 Access Token

用途：普通业务请求。

有效期：15-30 分钟，建议第一阶段 30 分钟。

payload：

```json
{
  "sub": "1",
  "sid": "session-uuid",
  "jti": "token-uuid",
  "role": "ADMIN",
  "token_version": 1,
  "type": "access",
  "iat": 1785559200,
  "exp": 1785561000
}
```

### 7.2 Refresh Token

用途：access token 过期后续期。

有效期：4-8 小时，建议第一阶段 8 小时。

payload：

```json
{
  "sub": "1",
  "sid": "session-uuid",
  "jti": "refresh-token-uuid",
  "token_version": 1,
  "type": "refresh",
  "iat": 1785559200,
  "exp": 1785588000
}
```

### 7.3 校验规则

access 校验：

```text
1. JWT 签名正确
2. exp 未过期
3. type == access
4. sid 在 Redis 中存在
5. Redis session.user_id == JWT sub
6. Redis session.token_version == JWT token_version
7. role 从 Redis session 或 PgSQL 当前账号读取，以服务端为准
```

refresh 校验：

```text
1. JWT 签名正确
2. exp 未过期
3. type == refresh
4. sid 在 Redis 中存在
5. token_version 匹配
6. 重新签发 access_token
```

## 9. FastAPI 依赖设计

### 9.1 当前用户依赖

预期形态：

```python
def get_current_user(
    authorization: str = Header(None),
) -> CurrentUser:
    ...
```

`CurrentUser` 建议字段：

```python
class CurrentUser(BaseModel):
    id: int
    sid: str
    role: str
    status: int
    full_name: str | None = None
    id_number_masked: str | None = None
    token_version: int
```

### 9.2 角色依赖

第一阶段只预留角色，不做复杂权限表。

```python
def require_role(*roles: str):
    def dependency(current_user: CurrentUser = Depends(get_current_user)):
        if current_user.role not in roles:
            raise HTTPException(status_code=403, detail="权限不足")
        return current_user
    return dependency
```

后续示例：

```python
@router.put("/system/config")
def update_config(
    req: ConfigUpdateRequest,
    current_user: CurrentUser = Depends(require_role("ADMIN")),
):
    ...
```

### 9.3 业务接口保护范围

第一阶段建议所有工作台接口都要求登录：

| 模块 | 路由 | 第一阶段要求 |
|---|---|---|
| 聊天 | `/chat/*` | 登录 |
| 文档 | `/documents/*` | 登录 |
| 评测 | `/evaluations/*` | 登录 |
| 系统配置 | `/system/*` | 登录，写操作建议 ADMIN |

如果担心一次改动过大，可以先保护写操作和管理操作，再保护聊天接口。但从政务工作台角度，建议默认全部保护。

## 11. 前端请求封装

新增统一请求函数，不要继续让每个 API 函数直接裸 `fetch`。

目标能力：

```text
1. 自动加 Authorization
2. 统一 JSON 解析
3. 统一错误消息
4. access 过期后自动 refresh
5. refresh 失败后退出登录
6. 避免多个并发请求同时 refresh
```

伪代码：

```typescript
async function request(path, options) {
  const accessToken = authStore.getAccessToken();
  const response = await fetch(path, {
    ...options,
    headers: {
      ...options.headers,
      Authorization: accessToken ? `Bearer ${accessToken}` : undefined,
    },
  });

  if (response.status !== 401) return readResponse(response);

  const refreshed = await refreshAccessTokenOnce();
  if (!refreshed) {
    authStore.logoutLocal();
    navigate("/login");
    throw new Error("登录已失效，请重新登录");
  }

  return retryOriginalRequest();
}
```

并发 refresh 处理：

```text
refreshPromise 存在时复用同一个 Promise
refreshPromise 完成后置空
```

## 12. Token 存储策略

第一阶段可以采用：

```text
access_token：内存 + sessionStorage
refresh_token：sessionStorage
```

更成熟的政务方案建议：

```text
refresh_token：HttpOnly Secure SameSite Cookie
access_token：内存态
```

如果当前工程没有 HTTPS 和 Cookie 统一部署条件，先用 `Authorization Bearer` 方案可以接受，但要在文档和配置里标注为开发/内网阶段方案。

不要把身份证号、密码、完整用户信息写入 localStorage。

## 14. 权限管理预留

第一阶段只做角色：

```text

ADMIN
SYSTEM
```

后续成熟 RBAC 表：

```sql
CREATE TABLE auth_role (
    id BIGSERIAL PRIMARY KEY,
    code VARCHAR(64) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE auth_permission (
    id BIGSERIAL PRIMARY KEY,
    code VARCHAR(128) UNIQUE NOT NULL,
    name VARCHAR(100) NOT NULL,
    resource VARCHAR(100),
    action VARCHAR(50),
    created_at TIMESTAMPTZ NOT NULL DEFAULT now()
);

CREATE TABLE auth_role_permission (
    role_id BIGINT NOT NULL REFERENCES auth_role(id) ON DELETE CASCADE,
    permission_id BIGINT NOT NULL REFERENCES auth_permission(id) ON DELETE CASCADE,
    PRIMARY KEY (role_id, permission_id)
);
```

接口依赖后续可从：

```python
require_role("ADMIN")
```

演进到：

```python
require_permission("system.config.update")
```

前端路由也从：

```typescript
roles: ["ADMIN"]
```

演进到：

```typescript
permissions: ["system.config.update"]
```

## 19. 常见实现注意事项

### 19.1 不要只校验 JWT

每个业务请求必须同时校验：

```text
JWT 合法
Redis session 存在
token_version 匹配
```

否则退出登录、修改密码、管理员强制下线都无法立即生效。

### 19.2 不要在前端长期保存敏感数据

前端只保存必要登录态：

```text
access_token
refresh_token
user.id
user.full_name
user.role
user.id_number_masked
```

不要保存：

```text
完整身份证号
密码
完整 personal_info
```

### 19.3 不要使用 Redis KEYS 扫描下线

强制下线要通过：

```text
auth:user_sessions:{user_id}
```

拿到 sid 集合后逐个删除 `auth:session:{sid}`，再删除集合。

### 19.4 SSE 聊天接口也要带 token

当前聊天流式接口是 `POST /chat/stream`，不是浏览器原生 `EventSource`，因此可以继续用 `fetch` body stream，并在请求头里带：

```text
Authorization: Bearer <access_token>
```

如果后续改成 `EventSource`，要注意原生 EventSource 不方便设置自定义 Header，需要改用 Cookie 或 fetch stream。

### 19.5 修改密码后的体验

修改密码成功后不要继续停留在工作台。应提示：

```text
密码已修改，请重新登录
```

然后清空前端登录态并跳转 `/login`。
